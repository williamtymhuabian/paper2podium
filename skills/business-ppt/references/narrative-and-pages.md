# 商业叙事线与页面清单

## 0. 先选模式，再排页

| 模式 | 场合 | 页数 | 单页停留 | 谁在讲 |
|---|---|---|---|---|
| **展台循环版**（默认展出） | 展会/展厅大屏，无人值守 | 8–10 | 6–12s | 屏幕自己讲 |
| **公司介绍版** | 客户拜访、招商、官网下载 | 12–16 | 30–60s | 销售/负责人 |
| **客户提案版** | 已知客户的方案汇报 | 14–20 | 45–90s | 方案负责人 |
| **产品发布版** | 发布会、媒体、渠道大会 | 10–14 | 40–80s | 创始人/产品负责人 |

一套内容资产做三种输出（行业通行做法，时长为经验值而非统一标准）：
**15–30s 引流循环**（3–4 页，只讲"是什么+一个记忆点"）→ **60–90s 完整循环**（8–10 页）→
**3–5min 讲解版**（12–16 页，销售现场翻）。先做完整循环，再删出引流版、扩出讲解版。

## 1. 展台循环版（8–10 页，60–90 秒）

目标不是"讲完公司"，而是让路过的人在 3 秒内知道**你是什么品类、解决什么问题、下一步做什么**。

| 序 | 页面 | 停留 | 必须出现 |
|---|---|---|---|
| 01 | 封面：品牌 + 品类 + 一句主张 | 8s | 品牌名、做什么、展位号、二维码 |
| 02 | 一句话主张（宣言页） | 8s | 一句 14 字内的主张 + 三个支撑短语 |
| 03 | 问题：对方的处境 | 8s | 一个具体场景 + 一个代价数字（有出处） |
| 04 | 产品 hero：全幅场景 | 10s | 产品在真实场景中的样子 + 一句能力 |
| 05 | 能力三栏 | 10s | 3 个能力，每个一句人话 + 一个参数 |
| 06 | 证据：评测/实测数据 | 10s | 一个结论 + 一个对比数字 + 来源 |
| 07 | 场景三连（图） | 10s | 3 个应用场景，每图 4–6 字标签 |
| 08 | 交付方式 | 8s | 平台授权 / 数据评测 / 联合试点（按真实业务） |
| 09 | 信任状 + 联系 | 12s | 资质/伙伴/团队 + 二维码 + 展位号 |

**硬规则**
- 没有目录页、没有"谢谢观看"、没有团队全家福（除非团队是卖点）
- 每页正文 ≤ 3 行；每行 ≤ 12 字；标题 ≥ 48pt（1080p，3m 距离）
- 全片静音可懂：去掉声音后仍能知道"是什么、凭什么、怎么联系"
- 首尾要能无缝循环：尾页 CTA 与封面同一视觉锚点（品牌 + 二维码 + 展位号），回封面不突兀
- 二维码只在封面与尾页出现；每页页脚可保留展位号，不重复二维码
- 屏幕安全区：重要内容离边缘 ≥ 5%（防 overscan）；不要贴边放小字
- 展馆强光下避免大面积纯白；OLED 避免长时间高亮静态元素（用深色底 + 缓慢循环）

## 2. 公司介绍版（12–16 页）

主线：**一句话我们是谁 → 数字概览 → 我们解决什么问题 → 产品/服务 → 能力 → 案例 →
伙伴/资质 → 团队 → 联系**。每一页只回答一个问题，页序可按受众调整（客户重案例，招商重模式）。

| 章 | 页数 | 页面 | 一句话主张示例 |
|---|---|---|---|
| 01 我们是谁 | 3 | 封面 → 一句话定位 → 数字概览 | "让无人机听懂人话，自己找到目标" |
| 02 为什么是我们 | 2 | 问题与代价 → 旧方案为何不够 | "传统方案换一个场景就要重标一次" |
| 03 我们做什么 | 3 | 产品/服务矩阵 → 核心能力 2 页 | "一个平台，覆盖数据、训练与评测" |
| 04 证据 | 3 | 案例 2 页 → 伙伴/资质 | "试点场景搜索时间下降 62%" |
| 05 是谁在做 | 2 | 团队 → 里程碑 | "来自具身导航一线研究团队" |
| 06 下一步 | 1 | 联系/CTA | "带上你的场景，两周做一次评估" |

- 公司介绍允许章节过渡页，但不超过 3 张；小公司可完全省略
- 数字概览必须真实可审计：成立年份、客户数、项目数、专利数、覆盖城市；没有就换成
  "团队 12 人 / 3 个行业场景 / 2 项发明专利"这类可核验的小数字，不编市占率
- 团队页只放关键 3–5 人：照片统一背景与构图，姓名 + 角色 + 一句"他解决什么问题"，
  不写整段履历；顾问/投资方单独一行小字，避免暗示雇佣关系
- 英文版不是逐字翻译：标题更短、术语统一（UAV / embodied navigation / VLN），
  中英混排时英文用 Arial、字号略小 1–2pt

## 3. 客户提案版（14–20 页）

主线：**执行摘要（先给结论）→ 我们对你问题的理解 → 不解决的代价 → 目标与成功指标 →
方案 → 实施计划 → 案例证据 → 投入产出 → 风险与保障 → 下一步**。

| 部分 | 页数 | 要点 |
|---|---|---|
| 封面 | 1 | 客户名 + 提案主题 + 日期 + " Confidential"（如需） |
| 执行摘要 | 1 | 3 条：你的问题、我们的方案、预期结果（数字）——一页讲完 |
| 理解你的业务 | 1–2 | 用客户的语言复述其流程/指标，引用访谈或公开信息；这页决定信任 |
| 代价 | 1 | 不改变现状的成本（人力/时间/合规/机会），标注测算口径 |
| 目标 | 1 | 双方认可的 2–3 个成功指标与基线，写清测量方式 |
| 方案总览 | 1 | 一张端到端流程图（现状 → 方案后），不堆功能 |
| 方案细节 | 3–5 | 每个模块一页：做什么、怎么接、谁负责、边界在哪 |
| 实施计划 | 1–2 | 周为单位的时间轴、里程碑、客户侧投入（人天） |
| 案例证据 | 1–2 | 同行业优先；写清"和我们像在哪、结果如何测量" |
| 投入产出 | 1 | 三档报价（好/更好/最合适）或 TCO/ROI 测算；口径透明 |
| 风险与保障 | 1 | 交付风险、数据安全、SLA、退出机制——主动写，反而加分 |
| 下一步 | 1 | 具体日期与动作（评审会/试点启动/合同节点），不是"期待合作" |
| 附录 | 1–3 | 技术架构、安全合规、团队简历、完整报价表，备查不主讲 |

- 前 3 页必须出现客户名字与客户的问题；否则就是公司介绍，不是提案
- 报价页用表格：方案档位 × 包含内容 × 价格/计费方式；不写"面议"除非确有此策略
- 所有客户 logo、案例数据需获授权；未授权用"某省级应急单位"匿名表述并注明
- 提案结尾的"下一步"必须可执行（日期+负责人+交付物），否则前面全部作废

## 4. 产品发布版（10–14 页）

主线：**hero → 行业转折 → 旧方案局限 → 新产品 reveal → 三个能力 → demo/场景 →
版本与价格 → 上市时间 → CTA**。

- Reveal 页只放产品名 + 一张主视觉 + 一句定位；之前不要提前泄露完整产品图
- 能力页最多 3 个，每个配一个"所以呢"（对用户的具体改变）
- demo 用真实录屏/实拍，标注"实时演示"或"模拟"；不要用渲染图冒充实拍
- 价格页讲清版本差异与适用对象；不公布价格时给"预约获取报价"的明确路径
- 发布会 deck 字更少、图更大，主讲人负责信息；页面只负责记忆点

## 5. 每页自检（写脚本前逐页填）

1. **3 秒记忆点**：这页观众记住哪一句/哪个数字？（≤ 15 字）
2. **证据**：图/数字/案例/资质，来源是什么？
3. **焦点**：全幅图 / 超大数字 / 一句大字，只有一个
4. **静音可懂**：不看备注能否看懂？
5. **下一步**：这页把观众推向什么动作？（继续看/扫码/提问）

五问有一问答不上，就重做这页，不要靠排版补救。

## 6. 高频提问 → 备查页

- 你们和 XX 有什么区别？→ 对比表（维度 ≤ 5，客观可验证）
- 数据安全/合规怎么做？→ 部署架构、等保/ISO、数据留存策略
- 交付周期与客户侧投入？→ 实施计划、RACI、人天估算
- 效果怎么衡量？→ 指标定义、基线、测量周期、失败退出条款
- 价格怎么构成？→ 报价拆解、计费口径、包含/不包含
- 团队是否稳定？→ 核心成员、股权/激励、顾问名单（获授权）

## 7. 命名与交付

- 文件名：`<公司>_公司介绍_2026.pptx`、`<公司>_<展会>_展台循环.pptx`、
  `<客户>_<项目>_提案_2026-11.pptx`
- 同时交付：`pdf/` 预览、`png/` 逐页图（展台备份播放）、`bg/` 背景、构建脚本、
  `讲稿_展台循环.md`（每页字幕 + 30s 口播 + 3min 讲解）、品牌资产文件夹
- 展台 U 盘里放三样：PPTX（已写入循环）、PDF（防字体缺失）、PNG 序列（防软件故障）；
  现场用 1080p 或 4K 实测一遍，二维码实扫一遍
